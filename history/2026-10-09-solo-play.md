# Solo play for local testing

## Context
Before the engine migration, Rémi wants to test game modes alone at home: play both the white and the black moves from one browser.

## Decided
- **Development only.** In production, the server stays strictly authoritative: one player = one side.
- A game opened with `?solo` gives **both sides** to the player who opens it. The protocol gets a new seat, `"both"`. The home page shows a **Create a solo game** button in development.
- Gated by `import.meta.env.DEV` on the client **and** in the Worker (the Cloudflare Vite plugin runs the Worker through Vite, so the flag is `false` in the production build and the solo code is dropped). No environment variable or `.dev.vars` file needed.
- Seats are tied to the token: reconnecting to a solo game, even without `?solo`, gives both sides back. A second visitor is a spectator.
- The board stays oriented white-side-down in solo play.

## Points of attention
- The `"both"` seat will survive the `Variant` → `GameMode` migration: `view(state, viewer)` must accept it (or the server maps it to a full view).
